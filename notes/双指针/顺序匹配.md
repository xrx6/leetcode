# 顺序匹配

> 子序列判定:两串各一根指针——主串 t 的指针单向扫(驱动),模式 s 的指针只进不退(配上才前进)。
> 贪心:每个 s 字符配 t 中「当前位置之后最早的出现」,交换论证保证永不逼死——更早的匹配只留更多余量。
> 与 28 的分野一句话:子串不能跳字,失配要回退(π 表);子序列能跳字,失配即前进——贪心就够,永不需要 π。
> 进阶(k≥1e9 个 s 查同一个 t):把「扫到下一个 c」从运行期提到预处理期——跳表 nxt(序列自动机),单查 O(m) 不再扫 t(压表族,与 π 表、罗马面额表同宗)。
> 面试经典 150 题:392 · 同一子技巧的新题往对应小节追加

## 392. 判断子序列(简单)

**题意**:判断 s 是否为 t 的子序列(删 t 若干字符、不改变相对位置)。进阶:k≥1e9 个 s 依次查同一个 t,怎么办。

**怎么想到的**:子序列=「可跳字」的匹配。28 找子串时 t 一个字符都不能跳、失配还要回退;这里 t 可以随意不理 s 不需要的字符——骨架反而更简单:i 扫 t,j 等在 s,t 的每个字符要么正好是 j 在等的(配,j 前进),要么跳过。j 走到头即真;t 扫完 j 没到头即假。

贪心为什么对(交换论证):设存在任一嵌入 i₁<i₂<…<i_m。归纳可证贪心嵌入逐位 j_k≤i_k——j_{k-1}≤i_{k-1} 时,贪心取「j_{k-1} 之后 c_k 的最早出现」,而 i_k 是「i_{k-1} 之后的一个出现」,出发点更靠左,候选集更大,取到的最早只会更早或相等。每步都不吃亏 ⇒ 永不逼死。

**代码**(解法一,独立完成版,2026-11-03 一遍过 AC):

```cpp
int m=s.size();
int n=t.size();
if(m==0) return true;            // 空 s 恒真;守卫必要——无它 (空,空) 返假
if(m>n) return false;            // 纯提速:无它仍对,j 至多配 n 次 < m
for(int j=0,i=0;i<n;i++){        // i 单向扫 t 驱动,j 等在 s 只进不退
    if(s[j]==t[i]) j++;          // 配上才前进:贪心最早匹配
    if(j==m) return true;        // s 全配完即真,早退
}
return false;                    // t 扫完没配完:后面没有字符了
```

**坑**:

- 空 s 守卫救命(必爆):无守卫版 (s="",t="") 循环不进返假;(s="",t="x") 却侥幸对——空串 s[0] 有定义返回 '\0'(pos==size() 特权位,vector 同位 UB,语言参考·空 vector 下标节)。跳表/二分版空 s 循环不进天然真——**守卫要不要看骨架,不看成例**。
- m>n 提前返假纯提速(未爆):无它仍对,只是白扫一整串。
- 跳表忘 pos++:同一位置被相邻同字符反复白嫖,"aa"/"a" 误真(最小反例);建表先盖后抄:自盖被整行抄掉,"a"/"a" 误假。

**进阶(k≥1e9 个 s 查同一个 t)**:解法一每查 O(n) 扫 t,t 固定时这遍扫描是纯重复(1e9×1e4=1e13 次比较死)。两条压表路——同款贪心,只有「找下一个 c」从循环扫变成 O(1) 查表 / O(log n) 二分:

```cpp
// 跳表/序列自动机:预处理 O(26n) 一次,单查 O(m),t 再也不扫
int n=t.size();
vector<array<int,26>> nxt(n+1);
nxt[n].fill(n);                       // 哨兵 n = 「没有」
for(int i=n-1;i>=0;i--){
    nxt[i]=nxt[i+1];                  // 先整行抄右边
    nxt[i][t[i]-'a']=i;               // 再盖自己(反了自盖被抄掉)
}
int pos=0;
for(char c:s){
    pos=nxt[pos][c-'a'];              // 一步跳到 c 的首现:扫描变跳转
    if(pos==n) return false;
    pos++;                            // 严格在后(漏了同位白嫖)
}
return true;
```

```cpp
// 每字母位置表+二分:预处理 O(n),单查 O(m log n),拿 log 换 26 倍表
vector<vector<int>> pos(26);
for(int i=0;i<n;i++) pos[t[i]-'a'].push_back(i);   // 每字母升序下标表
int start=0;
for(char c:s){
    auto& v=pos[c-'a'];
    auto it=lower_bound(v.begin(),v.end(),start);  // 首个 >= start(=上次+1)
    if(it==v.end()) return false;
    start=*it+1;
}
return true;
```

部署形态:LeetCode 单查接口下表每查重建 O(26n),单查反而不如解法一——它的主场是海量查询:表建一次按 t 内容缓存住,预处理只付一次,吃 k 次查询。解二拿 26 倍表换 O(1) 一步,解三拿 log n 换表——按内存与查询量选。单查 O(m) 已是「读 s」的下界,到底了。

**复杂度**:解一 O(n+m)/O(1);解二预处理 O(26n)/O(26n)、单查 O(m);解三预处理 O(n)/O(n)、单查 O(m log n);DP 基线 O(nm),暴力枚举 t 子序列 2^n 不可行。

**状态**:独立完成(2026-11-03,一遍过 AC);进阶跳表/二分由讲解补入。

## 原理

贪心最早匹配的正确性:上文交换论证展开——反证最直观:若贪心「配太早」导致后面配不完,则任一可行嵌入在同一步取的是更晚的位置,更晚只会让后面的余量更小——它都能配完,贪心更能。所以贪心嵌入逐位 ≤ 任一可行嵌入,存在可行嵌入 ⇒ 贪心必达。

为什么解法一需要空 s 守卫、跳表/二分版不需要:同一个「空 s 恒真」的语义,两个骨架的死法不同——解一以 t 为驱动,(空,空) 时循环不进,直接落 return false;解二/三以 s 为驱动,空 s 循环不进,天然落 return true。守卫要不要看骨架,不看成例。

跳表与 π 表同为压表族,压的东西不同:π 表压「失配后从已配窗口里能救回几格」(救的是回退),跳表压「每个位置后每个字母在哪」(免的是扫描)。为什么 392 不需要 π:t 允许跳字,s 的每个字符独立找位置,不存在「窗口作废」;28 的 t 必须连续,窗口一断就作废,才需要从窗口里抢救起点。**能跳字就不用回退**——这一句说尽 28 与 392 的分野;也正因此子序列判定不需要任何表就能线性,子串查找要线性就必须带 π 表——思维重量全在表上。
