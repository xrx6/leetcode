# 双向扫描(左右各一趟,答案取 max)

> 框架总览:当一个点同时被「左边传来的约束」和「右边传来的约束」夹住时,单向一趟只能看到一半信息。拆开处理:左右约束各自是一条**严格链**(链头 1,每步 +1),一条一维链 DP 一次线性扫描就能求出;两趟扫完,每个点的答案 = max(左链值, 右链值)。同族骨架「从左累计一遍、从右累计一遍、按运算合并」:238 的 L/R 前缀积是乘法版,134 的前缀和视角是加法版,这里的链长是 max 版。

## 题目:135 分发糖果(困难)

### 题意

n 个孩子排一排,`ratings[i]` 是评分。每人至少 1 颗糖;相邻两人中评分更高的必须拿严格更多的糖。求最少总糖数。注意**相等评分不产生任何约束**(示例 [1,2,2] → 1,2,1)。

### 怎么想到

先看错误的第一反应,也是我自己的原解:「相邻不等就 +1」,即 `count = n + Σ[相邻不等]`。它丢了两样东西:

- **丢方向**:下降对(右边孩子评分更低)不该加。[1,3,2] 原解给 5,正解 4——多算。
- **丢链长**:同向连赢是链式累加。[1,2,3] 原解给 5,正解 6——少算,3 号要赢 2 号、2 号要赢 1 号,传递到 3 号就是 3 颗。

题面给的两个示例恰是谷形([1,0,2])和单升长度 2([1,2,2]),每处不等恰好都只差一颗,巧合通过,把结构问题掩盖了。**糖果数不由「赢了几次比较」决定,由「在链上的位置」决定。**

正路:candy[i] 被两张下界证书夹住——

- `left[i]`:以 i 结尾的严格上升链长度。链上每步强迫 +1、链头至少 1,归纳可证**任何**可行方案都有 candy[i] ≥ left[i];
- `right[i]`:以 i 开头的严格下降链长度,同理 candy[i] ≥ right[i]。

于是 candy[i] ≥ max(left[i], right[i]) 对一切可行方案成立;而恰好取等号的方案是可行的(见坑3)→ 它**逐点最小** → 总和最小。left/right 各是一条一维链 DP,正扫一遍、倒扫一遍,就地取 max 合并。

### 代码

```cpp
int candy(vector<int>& ratings) {
    int n = ratings.size();
    vector<int> candy(n, 1);              // 规则①:每人至少 1 颗
    for (int i = 1; i < n; i++)           // 左→右:只看左边,candy[i]=左链长
        if (ratings[i] > ratings[i - 1])
            candy[i] = candy[i - 1] + 1;
    for (int i = n - 2; i >= 0; i--)      // 右→左:只看右边,合并取 max
        if (ratings[i] > ratings[i + 1])
            candy[i] = max(candy[i], candy[i + 1] + 1);
    int total = 0;
    for (int c : candy) total += c;
    return total;
}
```

### 坑

1. **触发条件是「严格更高」,不是「不相等」**:相等两边给一样多(甚至都给 1)完全合法。
2. **第二趟用 max 不用覆盖**:倒扫更新时 candy[i] 已背着左约束,直接覆盖会把左边的要求丢掉。
3. **两趟为什么从不打架**(可行性的关键一步):边 (i-1,i) 上 ratings[i] 更高时,败者 i-1 在右扫的判断 `ratings[i-1] > ratings[i]` 上直接出局,右链值必为 1 → candy[i-1] = left[i-1];而 candy[i] ≥ left[i] = left[i-1]+1,严格胜出。对称另一边。每条边上只有赢家的「胜侧链」在起作用,两趟各管半边、互不冲突。
4. **数值口径**:最坏严格递增,总和 = n(n+1)/2 ≈ 1.25e9 < INT_MAX ≈ 2.1e9,int 撑得住(对 n≤7 全穷举验证过该上界)。
5. 写条件时自查一眼:`A!=B || B!=A` 两半互为反写,恒等于前一半——原解里就写了个这样的空架子。

## 原理

- **最小性 = 下界 + 可达**:max(left,right) 是一切可行解的逐点下界(链上归纳);取等号的方案又可行(坑3)→ 它就是逐点最小。**逐点最小 ⇒ 总和最小**,这是比「总和最小」更强的性质——每项独立取到各自下界,不靠任何项之间的补偿/交换论证。
- **贪心证明的通用姿势**:和 134 同味——134 是「两张证书管一件事」(段淘汰管「除了它还能是谁」,total 终审管「连它都不行吗」),135 是「两张证书夹一点」(左链、右链)。最小性证明 = 给出下界(任何方案都压不过)+ 证明达到下界(这个方案真的行),双向夹逼。
- **为什么 134 一趟、这里必须两趟**:134 合并两侧信息的运算是**和**(total 边扫边同步累加,一个变量装下另一半);135 合并的运算是 **max**,且右链值取决于还没扫到的未来,单变量装不下,老老实实两趟。存在 O(1) 空间的升/降段计数变体(up/down/peaks 三个计数器把两趟信息也塌缩掉,峰值处取 max(up,down) 处理既升又降),属进阶方向。
- **链 DP 的身份**:left[i] = left[i-1]+1 或 1,就是「以 i 结尾的最长严格上升链」的 DP;所谓贪心解,骨子里是两条方向相反的一维 DP 加 max 合并——又一次印证「贪心 = 有结构的 DP 的瘦身」(见同目录《DP到贪心的坍缩》)。
