# 双向扫描(左右各一趟,答案取 max)

> 框架总览:当一个点同时被「左边传来的约束」和「右边传来的约束」夹住时,单向一趟只能看到一半信息。拆开处理:左右约束各自沿链累计(严格链长度、前缀/后缀积、前缀/后缀最大……),一维链 DP 一次线性扫描就能求出;两趟扫完,逐点按运算合并。同族骨架「从左累计一遍、从右累计一遍、按运算合并」:238 的 L/R 前缀积是乘法版,134 的前缀和视角是加法版,135 的链长是 max 版,42 的前缀/后缀最大是 min 版。

## 题目:135 分发糖果(困难)

### 题意

n 个孩子排一排,`ratings[i]` 是评分。每人至少 1 颗糖;相邻两人中评分更高的必须拿严格更多的糖。求最少总糖数。注意**相等评分不产生任何约束**(示例 [1,2,2] → 1,2,1)。

### 怎么想到

先看错误的第一反应,也是我自己的原解:「相邻不等就 +1」,即 `count = n + Σ[相邻不等]`。它丢了两样东西:

- **丢方向**:下降对(右边孩子评分更低)不该加。[1,3,2] 原解给 5,正解 4——多算。
- **丢链长**:同向连赢是链式累加。[1,2,3] 原解给 5,正解 6——少算,3 号要赢 2 号、2 号要赢 1 号,传递到 3 号就是 3 颗。

题面给的两个示例恰是谷形([1,0,2])和单升长度 2([1,2,2]),每处不等恰好都只差一颗,巧合通过,把结构问题掩盖了。**糖果数不由「赢了几次比较」决定,由「在链上的位置」决定。**

正路:candy[i] 被两张下界证书夹住——

- `left[i]`:以 i 结尾的严格上升链长度。链上每步强迫 +1、链头至少 1,归纳可证**任何**可行方案都有 candy[i] ≥ left[i];
- `right[i]`:以 i 开头的严格下降链长度,同理 candy[i] ≥ right[i]。

于是 candy[i] ≥ max(left[i], right[i]) 对一切可行方案成立;而恰好取等号的方案是可行的(见坑3)→ 它**逐点最小** → 总和最小。left/right 各是一条一维链 DP,正扫一遍、倒扫一遍,就地取 max 合并。

### 代码

```cpp
int candy(vector<int>& ratings) {
    int n = ratings.size();
    vector<int> candy(n, 1);              // 规则①:每人至少 1 颗
    for (int i = 1; i < n; i++)           // 左→右:只看左边,candy[i]=左链长
        if (ratings[i] > ratings[i - 1])
            candy[i] = candy[i - 1] + 1;
    for (int i = n - 2; i >= 0; i--)      // 右→左:只看右边,合并取 max
        if (ratings[i] > ratings[i + 1])
            candy[i] = max(candy[i], candy[i + 1] + 1);
    int total = 0;
    for (int c : candy) total += c;
    return total;
}
```

### 坑

1. **触发条件是「严格更高」,不是「不相等」**:相等两边给一样多(甚至都给 1)完全合法。
2. **第二趟用 max 不用覆盖**:倒扫更新时 candy[i] 已背着左约束,直接覆盖会把左边的要求丢掉。
3. **两趟为什么从不打架**(可行性的关键一步):边 (i-1,i) 上 ratings[i] 更高时,败者 i-1 在右扫的判断 `ratings[i-1] > ratings[i]` 上直接出局,右链值必为 1 → candy[i-1] = left[i-1];而 candy[i] ≥ left[i] = left[i-1]+1,严格胜出。对称另一边。每条边上只有赢家的「胜侧链」在起作用,两趟各管半边、互不冲突。
4. **数值口径**:最坏严格递增,总和 = n(n+1)/2 ≈ 1.25e9 < INT_MAX ≈ 2.1e9,int 撑得住(对 n≤7 全穷举验证过该上界)。
5. 写条件时自查一眼:`A!=B || B!=A` 两半互为反写,恒等于前一半——原解里就写了个这样的空架子。

## 题目:42 接雨水(困难)

### 题意

n 根宽度为 1 的柱子,高度 `height[i]`。下雨后柱子之间能接多少水。

### 怎么想到

先看错误的第一反应,也是我自己的原解:「看邻居落差」——`water[i] ≈ min(左邻落差, 右邻落差)`。它和 135 的「数不等对」同病:**盯的是边,丢的是沿链累计的结构**。挡水的是两侧**最高的墙**(盆沿),不是隔壁那根柱子。

- **丢链长**:隔壁可能比你矮,但更远处有一根高墙。[4,2,0,3,2,5] 下标 2(height=0)左邻只给 2、正解 4——左边真正的墙是下标 0 的 4,中间那根本身也在水下。
- **两侧都可能丢**:同题下标 3(height=3)右邻 2 比它矮、原解给 0,正解 1——右墙是 5。该例总和 5≠9。

正路:candy[i] / water[i] 被两侧**盆沿**夹住——

- `leftMax[i] = max(height[0..i])`:左边最高的墙(含自己),前缀最大;
- `rightMax[i] = max(height[i..n-1])`:右边最高的墙(含自己),后缀最大;
- `water[i] = min(leftMax[i], rightMax[i]) - height[i]`:水位不超过较矮的那面墙,再减去柱子本身占掉的空间。

两端各扫一趟求 L/R,逐点合并。两端(i=0 / i=n-1)公式自动给 0——一侧没有墙,水从缺口流走。

### 代码

```cpp
int trap(vector<int>& height) {
    int n = height.size();
    if (n == 0) return 0;
    vector<int> leftMax(n), rightMax(n);
    leftMax[0] = height[0];
    for (int i = 1; i < n; i++)
        leftMax[i] = max(leftMax[i - 1], height[i]);
    rightMax[n - 1] = height[n - 1];
    for (int i = n - 2; i >= 0; i--)
        rightMax[i] = max(rightMax[i + 1], height[i]);
    int c = 0;
    for (int i = 0; i < n; i++)
        c += min(leftMax[i], rightMax[i]) - height[i];
    return c;
}
```

### 坑

1. **盆沿不是邻居**:累计的是「至今最高」,递推 `leftMax[i]=max(leftMax[i-1], height[i])`;写成 `height[i]-height[i-1]` 就退回原解。
2. **别忘了减柱高**:`min(L,R)` 是水位,柱子本身不是水。
3. **leftMax/rightMax 含自己**:初值取 `height[0]` / `height[n-1]` 再递推 max;合并时 min 恰好让两端自动得 0。
4. **合并运算对照 135**:135 两侧是「必须满足的要求」→ max(取更严);42 两侧是「不能超过的盆沿」→ min(取更松的瓶颈)。骨架同,运算不同。

## 原理

- **最小性 = 下界 + 可达**:max(left,right) 是一切可行解的逐点下界(链上归纳);取等号的方案又可行(坑3)→ 它就是逐点最小。**逐点最小 ⇒ 总和最小**,这是比「总和最小」更强的性质——每项独立取到各自下界,不靠任何项之间的补偿/交换论证。
- **贪心证明的通用姿势**:和 134 同味——134 是「两张证书管一件事」(段淘汰管「除了它还能是谁」,total 终审管「连它都不行吗」),135 是「两张证书夹一点」(左链、右链)。最小性证明 = 给出下界(任何方案都压不过)+ 证明达到下界(这个方案真的行),双向夹逼。
- **为什么 134 一趟、这里必须两趟**:134 合并两侧信息的运算是**和**(total 边扫边同步累加,一个变量装下另一半);135 合并的运算是 **max**,42 是 **min(L,R)-h**,且右链/右墙值取决于还没扫到的未来,单变量装不下,老老实实两趟。存在 O(1) 空间的升降段计数变体(135)与双指针/单调栈变体(42),属进阶方向。
- **链 DP 的身份**:135 的 left[i] = left[i-1]+1 或 1,是「以 i 结尾的最长严格上升链」;42 的 leftMax[i] = max(leftMax[i-1], height[i]),是「以 i 结尾的前缀最大」。所谓贪心解,骨子里是两条方向相反的一维 DP 加合并——又一次印证「贪心 = 有结构的 DP 的瘦身」(见同目录《DP到贪心的坍缩》)。
- **合并运算一览**(同骨架、不同语义):238 乘(两侧都不含自己,排除乘积)、135 max(两侧都是下界证书,取更严)、42 min(两侧都是上界盆沿,取瓶颈)。看懂「左右各扫一遍」之后,分题的功夫在**每趟记什么、按什么运算合并**。

## 自测问题

1. 原解「数相邻不等对」(135)错在哪两处?各举一个 n=3 最小反例。
2. 为什么**任何**可行方案都满足 candy[i] ≥ left[i]?用链上归纳说一遍。
3. max(left,right) 为什么可行?关键一步「败者在胜者方向的链值必为 1」怎么证?
4. 「逐点最小 ⇒ 总和最小」为什么成立?它比「总和最小」强在哪,证明中哪一步用到了它?
5. 134 能一趟扫完、135 必须两趟,根本差别在两侧信息合并的运算是什么?
6. 238 的 L/R 前缀积和本题的 left/right 是什么关系?「从左一遍、从右一遍、合并」这个骨架还有哪些运算版本?
7. 42 原解「min(左邻落差, 右邻落差)」错在哪?[4,2,0,3,2,5] 下标 2 和下标 3 各自错什么?
8. 135 合并用 max、42 用 min,语义差别是什么?(下界证书 vs 上界盆沿)
9. 42 为什么必须减 height[i]?不减构造一个最小反例。
10. 238 / 135 / 42 各自「每一趟记什么、按什么运算合并」?填一张三行对照表。
